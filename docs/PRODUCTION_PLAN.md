## Critical path and parallel tracks

The immediate path is candidate integration → complete AI/gameplay acceptance → configure and verify the host → publish the current-game beta → implement authoritative persistence → qualify AI continuity → expand the world. Recoverable local saves and the existing playable loop remain requirements throughout.

The existing stamp plan retains identity → wallet acceptance → owner-approved outgoing transfers → tested trading → full shared multiplayer/PvP. A technical server alpha can prove authority and persistence without enabling those features. This plan does not declare unfinished transfer/trading gates complete or silently promise their delivery inside P2/P3. If they are included in the full shared-town release, their completion becomes an additional release dependency and extends its forecast. Record that scope decision in P0.

## Hosting and operations work

P0/P1 must record the actual host, deployed revision, domain, responsible operator and current charges; verify runtime/database support, genuine sign-in, shared durable AI accounting, provider availability and tariffs. Preserve the current host during preparation unless a later hosting decision authorizes a move. P2 additionally needs a durable scheduler/worker and canonical world storage. P6 adds isolated compute and its own resource accounting; choose providers only after capability and cost checks.

Before publication, make the candidate reviewable: source revision, relevant CI/browser/human evidence, database migration procedure, backup/restore and rollback instructions, known limitations, expected monthly operating cost and feature switches. Then obtain the release instruction and record the actual deployed build and smoke checks in RELEASE.md. Source integration alone is never a release receipt.

Before admitting continuous worlds, measure concurrency, tick/queue delay, provider failures, database growth and cost per active avatar-hour. Set capacity and per-account/global spending limits from those measurements, with a useful fallback when inference or accounting is unavailable. Define recovery time and acceptable data-loss targets, perform a coherent restore and rehearse operator intervention. Free model qualification alone is not guaranteed production capacity.

The Freeman Show's existing **£100 first-month cloud/content ceiling** is a recorded show budget, not automatic authorization to purchase shared-world hosting, sandbox capacity or hardware. Record a combined operating budget and what is already spent before proposing additional services. No purchase, provider migration, model call or deployment is made by this plan.
