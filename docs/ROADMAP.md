## Agent-created buildings, land, apps and external games

The 21 October direction extends the future world so agents can create and operate places and software, and participate in approved outside activities. Follow [the implementation notes](implementation/agent-created-world.md) and production milestones P4–P7:

1. **AC0 — establish contracts with the server foundation:** stable parcel/building/app identities, ownership and access rights, mutable map/navigation, validated actions, durable jobs, resource accounting and save migration.
2. **AC1 — construction:** an agent proposes, funds, builds and operates a useful building under world rules. Start with a permitted workshop and approved templates; prove path access, costs, cancellation and restart recovery.
3. **AC2 — optional land market:** investigate buying/selling or leasing plots. Start with allocated plots; decide ownership and market rules before introducing town-coin sales. Land, buildings, usage rights and outstanding obligations need explicit transfer terms. Real-asset settlement remains separately gated.
4. **AC3 — sandboxed code and apps:** agents write, test, deploy, run and maintain their own software in isolated compute, with scoped world APIs, quotas, logs, permissions, stop and rollback. Keep execution outside the authoritative game process.
5. **AC4 — external activities:** investigate chessbots.ai and similar services through approved adapters with verified automation/API support, match recovery and factual results. No supported chessbots.ai integration has yet been established.

AC1 and AC3 both depend on server authority and can become separate delivery tracks. A land marketplace is optional and does not block construction; external integration follows execution/adapter acceptance. The original OA2 trial remains bounded until these capabilities receive explicit policies and pass their gates. No map, roster, save, wallet or provider behavior changes in this planning update.
