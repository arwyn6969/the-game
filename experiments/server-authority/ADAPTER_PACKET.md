## Minimal membership and allowed proposals

The coordinator approved this mapping for the synthetic local harness only: create one synthetic server world, distinct from `town.identityRegistry.worldId`. Its server-only membership contains all eight fixed roles, each with a stable canonical character ID and a portable `characterRef` mapping. Only `player` maps to `account:adapter-owner`; the seven NPCs have no player-account owner and remain simulation-controlled. A second fake account is used solely for denial tests. The supplied trusted in-process principal is not real authentication.

Only the fake owner may issue quoted player actions, delegate or reclaim the player. The `target` NPC of a conversation/quote is not the acting character and confers no NPC control. Synthetic owner membership, controller revisions, leases and outbox records never appear in portable exports. Reopening a journal restores the same membership; another imported copy cannot overwrite it or claim it using identical portable IDs.

Keep two distinct job classes: (1) real NPC `ThinkJob` records returned by `stepMinute`, completed through the fake `offlineResult`/`applyResult` path under simulation authority; (2) an explicit delegated-player proposal under the player's revocable controller, limited initially to one legal cardinal movement. Do not repurpose NPC planning as permission to control the player. Human `applyPlayerAction` demonstrates actual funded work; delegated workers cannot accept a new shift, borrow, spend or move funds. Movement is an isolated adapter proposal validated with the real map, not a change to `TownApp` or existing navigation APIs.

## Atomic draft, receipt and outbox contract

1. Resolve world membership and trusted principal; check action fingerprint/receipt before effects. A command has **two distinct IDs**: outer request idempotency ID, and the existing engine's quoted `action.id`. Never substitute the outer ID for a displayed quote ID.
2. Clone the full envelope/Town into a private draft. Apply at most one quoted choice, clock step, controller transition or outbox completion. Reject failed choices without publishing their draft. Retain the current global revision check; a slow result crossing any tick is stale until explicitly re-evaluated under a new job/action ID.
3. For a tick, call `stepMinute(draft.town, true)`. Capture its returned `ThinkJob` and observation/controller binding in a durable pending outbox record **in the same commit** as the changed Town and tick receipt. Marking `callUsed` or changing the clock must not survive without its corresponding outbox evidence.
4. Fake inference reads a copied observation outside the transaction. Completion rechecks job identity/status, world observation, relevant controller/policy/lease fences and result scope. Apply allowed results to a fresh draft, then persist the resulting Town, completion receipt and completed/rejected job status together. A rejected stale result cannot alter the Town. Reclaim changes the player fence and invalidates pending avatar proposals in its own atomic commit; it does not wait for a fake worker.
5. Run `auditEconomy` and structural/identity checks on the candidate; receipt records the actual result and the engine command/transaction IDs added by this action. Existing engine-generated economy IDs remain intact. Persist the **full Town**, outer receipt and outbox/controller/membership state together using synthetic durable local storage; publish views only after fsync/commit.
6. Recover from committed full-state records/checkpoints and receipts, without replaying engine calls or inference. An unacknowledged commit is reconciled by idempotency receipt. A repeated import can neither initialize books twice nor overwrite an established canonical world. Retain exact invalid import bytes and a recoverable rejection record without admitting the world.

`exportTown` is a **portable export**, not a full canonical transaction serializer: it deliberately clears paths and replay scrub. Store complete JSON-safe Town state in the internal journal; separately test the existing export/import contract and its documented omissions. `validateTown`/`readTownFile` can normalize the object being validated, so validate a copy and never run a migration silently on the live canonical instance after every transaction.

`applyResult` returns `void` and intentionally tolerates some partial edits. Its receipt must report the audited resulting state, not assert that every proposal field succeeded. `navigation.ts` also contains a Town-keyed `WeakMap` yield cooldown outside serialized state. Snapshot recovery prevents re-running past movement, but exact future pathing continuity after a draft/restart is not yet guaranteed; do not claim full deterministic browser/server equivalence or change navigation in this packet. Report any consequential divergence to the coordinator.
